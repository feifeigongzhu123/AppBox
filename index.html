还差几步，把 AppBox 挂到 GitHub

  1. 创建一个公开仓库（例如 AppBox），把整个项目推上去。
  2. 仓库 Settings → Pages，选择 Deploy from a branch，分支选 main，目录选 /(root)。
  3. 打开 assets/config.js，把 owner 填成你的 GitHub 用户名，repo 填仓库名，保存并推送。
  4. 创建细粒度令牌：GitHub 头像 → Settings → Developer settings → Personal access tokens → Fine-grained tokens。只授权这个仓库，权限选 Contents: Read and write。

    HOW TO USE

    使用指南

    AppBox 可以免费挂在 GitHub Pages 上：网页程序在线打开，安装包提供下载，上传需要密码。下面是完整用法。

    1怎么用这个站

    • 浏览：首页的卡片就是所有程序，点进去能看到介绍和具体的使用方法。
    • 查找：右上角可以搜名字、标签和介绍；顶部的分类可以只看某一类。
    • 打开：网页程序会在站内窗口直接运行，也可以单独开一页；可下载文件会触发下载。应用升级后重新打开就是新版，如果看到旧页面，点窗口右上角「刷新」。
    • 分享：每个程序都有独立链接，点「复制链接」发给别人，对方打开就直接到那个程序。
    手机上也能用，页面会自动适配窄屏。站点发布到网上之后，发给朋友一个网址就够了。

    2三种程序类型

    上传时按程序的实际形态选一种即可：

    类型适合什么访客看到
    网页程序 HTML / CSS / JS 做的工具、小游戏、练习页 「打开程序」，在站内窗口里运行
    外部网址 已经部署在别处的网页 「打开链接」，新窗口跳转
    可下载文件 exe、apk、zip、安装包、文档 「下载程序」，从 AppBox 下载
    网页程序只能访问自己目录里的文件。如果程序需要读取用户电脑上的文件，请用「可下载文件」或改成让用户手动选择文件。

    3上传程序

    第一步：打开站点

    GitHub 模式：直接访问你的 Pages 地址，一般是 https://用户名.github.io/仓库名/。

    本地模式：双击 start.bat，浏览器会自动打开 http://localhost:8080 。

    第二步：输入上传密码

    点顶部「上传」，输入上传密码。密码在 assets/config.js 里以哈希形式保存，不存明文。

    GitHub 模式下第一次还需要粘贴一次 GitHub 写入令牌。令牌只保存在本机浏览器里，用密码加密，不会进仓库；换电脑或换密码时重新粘贴即可。

    第三步：填写程序信息

    名称和「链接标识」是必填的。链接标识决定详情页地址，只能用小写字母、数字和短横线，例如 yingcitong。图标可以填一个字符，也可以用 assets/ 下的图片路径。

    「使用方法」一行写一步，用竖线分开标题和说明，例如：

    打开程序 | 点击开始按钮
选择词库 | 选今天要背的一组
开始记忆 | 认识的点「认识」，不熟的点「再记一次」

    第四步：选文件或填网址

    • 网页程序：选择整个程序文件夹，最外层要有 index.html。GitHub 模式会逐个文件提交到 apps/标识/；本地模式上传 zip，服务器会解压到同一位置。
    • 外部网址：直接填以 http:// 或 https:// 开头的地址。
    • 可下载文件：选一个文件，提交到 files/，访客点按钮就下载。

    GitHub 免费仓库单文件上限 100 MB，Pages 站点总量 1 GB，所以上传页把单个文件限制在 50 MB；更大的安装包建议放到 GitHub Releases。

    第五步：发布

    点「上传并发布」。GitHub 模式会把文件和信息提交到仓库，Pages 大约 1 分钟后更新；本地模式会立即生效。要换版本时，用同一个链接标识重新上传，会覆盖旧程序。

    4GitHub 免费上线

    AppBox 的 GitHub 模式是纯静态的，不需要服务器，也不需要付费：

    1. 推送仓库

    在 GitHub 新建一个公开仓库（建议叫 AppBox），把整个项目推上去。免费账号的 Pages 只能发布公开仓库，所以程序源码和文件都是公开的。

    2. 打开 Pages

    仓库 Settings → Pages，Source 选 Deploy from a branch，分支选 main，目录选 /(root)。保存后等一两分钟。

    3. 填仓库信息

    打开 assets/config.js，把 mode 保持为 github，填好 owner（用户名）和 repo（仓库名），推送后刷新站点。

    4. 创建写入令牌

    GitHub 头像 → Settings → Developer settings → Personal access tokens → Fine-grained tokens，新建令牌：只授权这个仓库，把 Contents 权限设为 Read and write。复制令牌，回到上传页粘贴一次。

    5. 上传并等待部署

    上传后，内容会作为一次提交进入仓库，Pages 自动重新发布，通常 1 分钟左右生效。可以在仓库的 Actions 页面看部署进度。

    免费额度：Pages 站点不超过 1 GB，带宽约 100 GB/月，仓库单文件上限 100 MB；单个 Release 文件小于 2 GiB。 学习类小工具完全够用。更大的安装包请放到 GitHub Releases，再在商店里填外部网址。

    目录结构很简单：网页程序在 apps/标识/，下载文件在 files/，程序列表在 data/apps.json。备份就是 git clone，换电脑不会丢。

    本地预览：把 mode 改成 server，双击 start.bat，上传会保存到本机；再改回 github 推送即可上线。

    5常见问题

    为什么不能直接放一个本地 HTML 链接？
    本地路径只有你这台电脑能打开，别人访问会 404。现在程序提交到 GitHub 仓库，通过 Pages 网址访问，谁打开链接都能用。
    上传密码不正确？
    密码只认 assets/config.js 里 passwordHash 对应的那一个，区分大小写，前后不要带空格。忘记密码时，用文件顶部注释里的命令重新生成哈希并替换。
    提示 GitHub 令牌无效或没有权限？
    令牌需要只授权当前仓库，并给了 Contents: Read and write；过期、复制不完整、或授权了别的仓库都会失败。重新生成一个再粘贴即可。
    发布后打开是 404 或旧页面？
    GitHub Pages 需要 1 分钟左右重新部署，去仓库 Actions 看进度。网页程序要确认文件夹最外层有 index.html；本地模式上传 zip 时也一样。
    网页程序为什么读不到电脑里的文件？
    网页程序运行在浏览器沙箱里，只能访问自己目录里的文件。需要读写本地文件时，选「可下载文件」，或让程序提供文件选择按钮。
    怎么更新已经发布的程序？
    在「上传」页用同一个链接标识重新提交，旧条目和文件会被覆盖。只想改介绍文字，也可以重新填写信息后提交。
    嵌入的应用升级后，AppBox 会自动更新吗？
    应用本身是直接加载原网址，升级发布后打开就是新版；AppBox 还会读取各站点的 VERSION 文件，自动更新详情页显示的版本号。浏览器或 Service Worker 可能缓存旧资源，必要时点站内窗口的「刷新」。
    第一次打开为什么慢？
    第一次要下载页面、脚本和音频，站内窗口会显示「正在加载…」。之后浏览器和应用自己的缓存会保留资源；支持离线的应用断网也能用。看到旧页面就点右上角「刷新」。
    卡片上的「打开次数」怎么算？
    按点击「打开程序」的次数累计，用的是公开计数器，不需要注册。同一个人多次打开会重复计数，不是独立访客数。
    上传的文件存在哪？怎么备份？
    网页程序在 apps/，下载文件在 files/，信息在 data/apps.json，都在仓库里。备份就是 git clone 或复制整个项目。
    密码能真正保护上传吗？
    密码只用于本机解锁和加密令牌；真正拦住写入的是 GitHub 令牌。因此仓库里看不到密码明文，也看不到令牌明文。请不要把密码和令牌发给别人。
    手机能上传吗？
    能，打开同一网址、输入密码并粘贴一次令牌即可。大文件和文件夹建议用电脑上传，更稳定。
